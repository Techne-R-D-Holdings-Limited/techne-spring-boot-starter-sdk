# 获取第三方密钥约定（App 端对接指南）

> 本文档写给 **app 端对接同学**：说明 app 如何安全地从服务端接口**获取第三方密钥**（如 Google Maps、Stripe、消息推送的 key/secret 等）。
> 整条链路：先拉服务端 RSA 公钥 → 用一次性 AES 会话密钥加密请求 → 服务端返回**逐字段 AES/GCM 加密**的密钥 → app 本地解密使用。
> 与 [`分页接口标准出参约定`](分页接口标准出参约定.md)、[`接口参数签名约定`](接口参数签名约定.md) 同属 app / web 联调规范。

---

## 1. 概述

每次请求由客户端生成一个**一次性的 AES 会话密钥**，用服务端 RSA 公钥加密后随请求带上；服务端用 RSA 私钥解出本次 AES 密钥，再用它对请求/响应中的**每个字段**做 AES/GCM 加密。

- **防泄露**：字段在传输中以密文存在，即使被截获也无法还原（密钥不在报文里）。
- **前向安全**：会话密钥每次请求不同，且服务端 RSA 密钥周期性轮换。
- **与 `@SystemSecurity` 的区别**：`@SystemSecurity(inDecode/outEncode)` 是**整包 RSA** 加解密；本方案是 **每请求一个 AES 会话密钥 + 字段级 AES/GCM**，更细、性能更好，二者不要混用在同一方法上。

---

## 2. 启用

在 `application.yml` 中开启（默认关闭，按注解 opt-in）：

```yaml
techne:
  session-key:
    enabled: true                 # 总开关，false 时即使加了注解也不生效
    agreed-token: "app-fixed-token-2026"  # 约定身份字符串，客户端用 RSA 公钥加密后放 token 字段；必填
    key-rotation-hours: 24       # RSA 密钥轮换周期（小时）
    key-grace-hours: 1           # 上一把私钥宽限保留时间（小时），应 >= 客户端公钥缓存时间
    # 下面两项同时配置时：使用固定静态密钥，不轮换（多实例部署推荐，集群安全）
    # private-key-base64: "MIIE..."
    # public-key-base64:  "MIIB..."
```

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `techne.session-key.enabled` | `false` | 总开关 |
| `techne.session-key.agreed-token` | 空 | 约定身份字符串，**启用时必填**；缺失会让所有被标记接口校验失败 |
| `techne.session-key.key-rotation-hours` | `24` | RSA 密钥轮换周期（小时）；仅未固定静态密钥时生效 |
| `techne.session-key.key-grace-hours` | `1` | 上一把私钥宽限保留时间（小时），应 ≥ 客户端公钥缓存时间 |
| `techne.session-key.private-key-base64` | 空 | 固定静态 RSA 私钥（Base64）；与公钥同时配置时生效，**不轮换** |
| `techne.session-key.public-key-base64` | 空 | 固定静态 RSA 公钥（Base64）；与私钥同时配置时生效 |

> **集群部署建议**：多实例下若各 pod 独立轮换密钥，公钥接口与加密请求可能落到不同 pod 导致解不开。两种解法：① 配置固定的 `private-key-base64` + `public-key-base64`（所有实例同一把密钥）；② 共享存储（如 Redis）统一密钥。推荐 ①。

## 3. 服务端 RSA 公钥

服务端通过 `RsaKeyManager` 管理 RSA 密钥，对外暴露**当前公钥**（客户端用它加密 `sessionKey` / `token`）：

```java
@RestController
public class KeyController {

    private final RsaKeyManager rsaKeyManager;

    /** 客户端先调用此接口获取服务端 RSA 公钥；客户端建议缓存 1 小时 */
    @GetMapping("/api/public/rsa/get-publicKey")
    public ResponseData<String> getPublicKey() {
        return ResponseData.retData(rsaKeyManager.getPublicKeyBase64());
    }
}
```

密钥来源二选一：
- **自动生成 + 轮换**（默认）：启动时生成 2048 位 RSA 密钥，`key-rotation-hours` 后轮换，保留上一把私钥 `key-grace-hours` 小时。
- **静态固定**：同时配置 `private-key-base64` + `public-key-base64` 时采用，不轮换，多实例天然安全。

## 4. 报文结构

### 4.1 请求信封（被 `@SessionKeyEncrypt` 标记的接口）

```json
{
  "sessionKey": "<RSA 加密的 32 字节 AES 密钥，Base64>",
  "token":      "<RSA 加密的约定字符串，Base64>",
  "payload":   {
    "pageNum":  "<AES/GCM 密文>",
    "keyword":  "<AES/GCM 密文>",
    "profile":  "<AES/GCM 密文（其内部为 JSON 字符串）>"
  }
}
```

- `sessionKey`：客户端生成的 AES 会话密钥，用服务端 RSA 公钥加密（PKCS#1 v1.5）。
- `token`：约定的 `agreed-token` 字符串，用服务端 RSA 公钥加密，用于身份校验。
- `payload`：**业务参数字段集合**，每个字段值都是用本次 AES 密钥加密后的密文。

### 4.2 响应（自动加密 `ResponseData.data` 的每一个顶层字段）

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "apiKey":   "<AES/GCM 密文>",
    "secret":   "<AES/GCM 密文>",
    "expireAt": "<AES/GCM 密文>"
  },
  "time": "...", "traceId": "..."
}
```

> 响应里 `code` / `message` 仍为明文；仅 `data` 的**顶层字段**被逐字段加密（List 元素同样逐条加密）。字段名不变，值变为密文，客户端逐字段解密即可。

## 5. 加密算法

### 5.1 解出会话密钥（服务端）

```
AES 会话密钥 = RSA_私钥解密(sessionKey)        // 32 字节 → AES-256
token 原文    = RSA_私钥解密(token)
校验         : token 原文 == agreed-token ?        // 不一致 → 4008
```

### 5.2 字段加解密（AES/GCM/NoPadding）

- 算法：`AES/GCM/NoPadding`，**128 位认证标签（16 字节）**，IV 随机 **12 字节**。
- **密文格式（与移动端约定一致）**：`Base64( IV(12B) ‖ 密文 ‖ GCM Tag(16B) )`

```
加密: IV = 随机12字节
      cipherText = AES-GCM( IV, 明文, key )
      输出  = Base64( IV ‖ cipherText )          // cipherText 尾部已含 16B 标签

解密: raw   = Base64解码( 密文 )
      IV    = raw[0..12)
      ct    = raw[12..]
      明文  = AES-GCM( IV, ct, key )
```

## 6. 注解用法（业务接口）

在 Controller 方法（或类）上标记 `@SessionKeyEncrypt`，**请求自动解密、响应自动加密**：

```java
@RestController
@RequestMapping("/app/user")
public class AppUserController {

    @SessionKeyEncrypt
    @PostMapping("/profile/update")
    public ResponseData<UserProfile> updateProfile(@RequestBody ProfileReq req) {
        // req 已经是解密后的明文对象（sessionKey / token / payload 由框架处理）
        return ResponseData.retData(buildProfile(req));
    }
}
```

客户端对该接口的请求体必须是 §4.1 的**信封**；服务端把 `payload` 解密后注入 `@RequestBody ProfileReq`。响应中 `data` 的每个顶层字段会被自动加密。

> 注意：被 `@SessionKeyEncrypt` 标记的方法**要求**请求体是信封格式；以明文 JSON 直接请求会解析失败。

## 7. 密钥下发接口（参考实现）

app 端的部分密钥通过服务端接口返回时，通常走「先取公钥 → 再换密钥」的引导流程。下方为服务端示例（手动使用 `RsaKeyManager` + `AesGcmFieldCryptor`，**不**加 `@SessionKeyEncrypt`，因为请求体就是 `{sessionKey, token}`，无 `payload`）：

```java
@Operation(summary = "v1.8.0 iOS Keys",
    description = """
    **前置**：先调用 GET /api/public/rsa/get-publicKey 获取服务端 RSA 公钥（客户端缓存 1 小时；服务端每 24 小时轮换）。
    **请求体**：sessionKey = 客户端生成的 32 字节 AES 密钥，RSA 加密(Base64)；token = 约定字符串 RSA 加密(Base64) 用于身份校验。
    **服务端处理**：1) RSA 私钥解密 sessionKey 得到 AES 密钥；2) RSA 私钥解密 token 并与约定串比对，不一致返回 token invalid；3) 用 AES/GCM 逐字段加密返回。
    **客户端解密**：Base64 解码字段值 → 前 12 字节为 IV，其余为密文(标签附后) → 用本地 AES 密钥 + IV 解密。""")
@PostMapping("/key/get-key-next")
public ResponseData<EncryptedKeyPayload> keyNext(@RequestBody KeyRequest req) {
    byte[] aesKey = rsaKeyManager.resolveAesKey(req.getSessionKey()); // 失败 → 4007 session key invalid
    rsaKeyManager.verifyToken(req.getToken());                       // 失败 → 4008 token invalid
    EncryptedKeyPayload payload = new EncryptedKeyPayload();
    payload.setApiKey(aesGcmFieldCryptor.encryptField(realApiKey, aesKey));
    payload.setSecret(aesGcmFieldCryptor.encryptField(realSecret, aesKey));
    return ResponseData.retData(payload);                         // 每个字段已由框架/手动 AES-GCM 加密
}
```

> 该接口与 §6 的业务接口共用 `RsaKeyManager` / `AesGcmFieldCryptor` 两个 Bean；区别仅在于它**手动**解密 `sessionKey`、`token` 并**手动**加密返回字段，因此**不**加 `@SessionKeyEncrypt`。

## 8. 调用方（app / 前端）参考实现

```java
// 1) 取服务端 RSA 公钥（缓存 1 小时）
String serverPublicKeyBase64 = rest.get("/api/public/rsa/get-publicKey");
RSA rsa = new RSA(null, serverPublicKeyBase64);

// 2) 生成一次性 AES 会话密钥（32 字节）
byte[] aesKey = new byte[32];
new SecureRandom().nextBytes(aesKey);
String sessionKey = rsa.encryptBase64(aesKey, KeyType.PublicKey);          // RSA 加密
String token      = rsa.encryptBase64("app-fixed-token-2026", KeyType.PublicKey);

// 3) 逐字段用 AES/GCM 加密请求参数
String enc(Object v) {
    byte[] iv = new byte[12]; new SecureRandom().nextBytes(iv);
    Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
    c.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(aesKey, "AES"), new GCMParameterSpec(128, iv));
    byte[] ct = c.doFinal(toJson(v).getBytes(UTF_8));
    byte[] out = concat(iv, ct);                                   // ct 尾部含 16B 标签
    return Base64.getEncoder().encodeToString(out);
}

// 4) 组装信封
Map<String,Object> payload = new LinkedHashMap<>();
payload.put("pageNum", enc(1));
payload.put("keyword", enc("techne"));
Map<String,Object> envelope = new LinkedHashMap<>();
envelope.put("sessionKey", sessionKey);
envelope.put("token", token);
envelope.put("payload", payload);
rest.post("/app/user/profile/update", envelope);

// 5) 响应：逐字段解密 data
String dec(String cipherBase64) {
    byte[] raw = Base64.getDecoder().decode(cipherBase64);
    byte[] iv = copyOfRange(raw, 0, 12);
    byte[] ct = copyOfRange(raw, 12, raw.length);
    Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
    c.init(Cipher.DECRYPT_MODE, new SecretKeySpec(aesKey, "AES"), new GCMParameterSpec(128, iv));
    return new String(c.doFinal(ct), UTF_8);
}
```

## 9. 错误码

| code | 含义 | 触发条件 |
|---|---|---|
| `4007` | `session key invalid` | `sessionKey` 用 RSA 私钥解不开（如服务端已轮换公钥，客户端需重新取公钥重试）；或 AES 密钥非法 |
| `4008` | `token invalid` | `token` 解密后与约定字符串不一致；或未配置 `agreed-token` |

> 错误码由 `GlobalExceptionHandler` 统一拦截 `TechneException` 返回，结构同统一响应壳：`{ "code": 4007, "message": "session key invalid", ... }`。

## 10. 备注与边界

1. **公钥轮换平滑过渡**：服务端轮换后保留上一把私钥 `key-grace-hours` 小时，持有旧公钥的客户端在该宽限期内仍能正常请求；客户端公钥缓存建议 ≤ 该宽限时间。
2. **字段加密范围**：`data` 的**顶层字段**（以及 List 的每个元素）被逐字段加密；嵌套对象会先序列化为 JSON 字符串再加密，客户端解密后得到 JSON 子对象。
3. **与签名/整包加密不混用**：`@SessionKeyEncrypt` 与 `@SystemSecurity(inDecode/outEncode)` 不要标在同一方法上。
4. **默认关闭**：`techne.session-key.enabled=false` 时，即使方法标了注解也不做任何加解密（透传）。
