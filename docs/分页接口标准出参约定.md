# 分页接口标准出参约定（app / web 调试用）

> 适用范围：所有返回列表且需要分页的接口。
> 本文档即前后端协议，调试同学直接按此对接，无需再追问后端。

---

## 1. 统一响应壳

所有接口（含分页接口）都包在统一响应里：

```json
{
  "code": 200,
  "message": "success",
  "data": { },
  "time": "2026-07-28T14:03:46.123Z",
  "traceId": "a1b2c3d4-..."
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 状态码，`200` 表示成功；非 `200` 一律按失败处理 |
| `message` | String | 提示文案，失败时给前端直接展示 |
| `data` | Object | 业务数据（分页接口里是下面的 `PageResult` 对象） |
| `time` | String | 返回时间（ISO-8601），调试排查用 |
| `traceId` | String | 日志追踪 ID，排查问题提供给后端 |

---

## 2. 入参约定（分页查询参数）

分页接口的请求参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pageNum` | Long | 是 | 当前页，**从 1 开始** |
| `pageSize` | Long | 是 | 每页条数；传 **`-1` 表示不分页**（返回全量） |
| `keyword` | String | 否 | 关键字模糊搜索 |
| `sortColumn` | String | 否 | 排序字段（驼峰，后端自动转下划线） |
| `sortAsc` | Boolean | 否 | 是否升序，默认降序（`false`） |
| `startTime` | String | 否 | 开始时间（ISO-8601） |
| `endTime` | String | 否 | 结束时间（ISO-8601） |

**请求方法**：分页查询统一使用 **`POST`**，查询条件以 JSON 放在请求体（body）。

> 说明：因为支持 `keyword` 模糊搜索等较复杂的查询条件，用 GET 把条件拼在 URL 上既受 URL 长度限制、语义也不直观，故统一走 POST 请求体。

**请求示例**（POST，body 为 JSON）：

```json
POST /api/orders/list
Content-Type: application/json

{
  "pageNum": 1,
  "pageSize": 10,
  "keyword": "订单",
  "sortColumn": "createTime",
  "sortAsc": false
}
```

> `sortColumn` / `startTime` / `endTime` 不是每个接口都有，以具体接口文档为准；但 `pageNum` / `pageSize` 是所有分页接口的公共参数。

---

## 3. 出参约定（标准分页对象 `PageResult`）

分页接口的 `data` 字段永远是如下结构：

```json
{
  "list": [
    { "id": 1, "name": "示例1" },
    { "id": 2, "name": "示例2" }
  ],
  "total": 235,
  "pageNum": 1,
  "pageSize": 10,
  "pages": 24,
  "hasNext": true,
  "hasPrevious": false,
  "metadata": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `list` | Array | **当前页数据集合**（注意：不是 `records`） |
| `total` | Long | 总记录数 |
| `pageNum` | Long | 当前页（**与入参同名**） |
| `pageSize` | Long | 每页条数（**与入参同名**） |
| `pages` | Long | 总页数 |
| `hasNext` | Boolean | 是否还有下一页 |
| `hasPrevious` | Boolean | 是否还有上一页 |
| `metadata` | Object | 可选附加数据（如合计/统计），没有则为 `null` |

> ⚠️ **字段名约定（最容易踩坑）**
> - 出参是 `pageNum` / `pageSize`，**不是** `current` / `size`
> - 数据列表字段是 `list`，**不是** `records`
> - `data` 里除了上表声明的字段，不要依赖任何其它字段（内部字段不对外暴露）

---

## 4. 不分页场景（`pageSize = -1`）

当入参 `pageSize = -1` 时：

- `list` 返回**全量**数据
- `pages = 1`、`hasNext = false`、`hasPrevious = false`
- `total` 等于实际返回的记录数

```json
{
  "list": [ /* 全部数据 */ ],
  "total": 58,
  "pageNum": 1,
  "pageSize": -1,
  "pages": 1,
  "hasNext": false,
  "hasPrevious": false,
  "metadata": null
}
```

---

## 5. 前端如何使用

- **翻页**：请求时 `pageNum` 递增；当 `hasNext = false` 时禁用"下一页"/"加载更多"。
- **总页数**：直接用返回的 `pages`；或自行用 `ceil(total / pageSize)` 计算。
- **总条数展示**：用 `total`。
- **首屏判断**：`pageNum = 1` 时 `hasPrevious` 必为 `false`。

---

## 6. 完整成功响应示例

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [
      { "id": 1001, "name": "订单A", "amount": 99.00 },
      { "id": 1002, "name": "订单B", "amount": 199.00 }
    ],
    "total": 235,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 24,
    "hasNext": true,
    "hasPrevious": false,
    "metadata": { "totalAmount": 23365.00 }
  },
  "time": "2026-07-28T14:03:46.123Z",
  "traceId": "a1b2c3d4-0001-4abc-8def-1234567890ab"
}
```

> 上例中 `metadata` 携带了"金额合计"这类非列表统计信息，仅在该接口有此需求时出现，没有则为 `null`。

---

## 7. 失败响应

失败时 `code != 200`，分页数据不返回（`data` 为 `null` 或仅含错误信息），例如：

```json
{
  "code": 1001,
  "message": "请求参数有误",
  "data": null,
  "time": "2026-07-28T14:05:10.000Z",
  "traceId": "b2c3d4e5-0002-..."
}
```

前端统一约定：**只要 `code != 200`，就按失败处理并展示 `message`**，无需关心 `data` 结构。
