# 接口参数签名约定（app / web 调试用）

> 适用范围：所有标注需要参数签名的关键 API。
> 本文档即前后端协议，调用方（app / web）按此生成签名，调试同学直接对接，无需再追问后端。

---

## 1. 概述

- **目的**：防止请求参数被篡改、防止请求被重放（防重放依靠 `nonce` 一次性 + `timestamp` 时效）。
- **机制**：基于 `@SystemSecurity` 注解声明 + Sa-Token 签名校验模板（`TechneSaSignTemplate`，Sa-Token `1.42.0`）。
- **默认行为**：
  - 只要配置了 `sa-token.sign.secret-key` 且接口未声明放弃签名，就会**自动校验**参数签名；
  - 只要校验了签名，就一定会校验客户端时间戳（此时 `@SystemSecurity(passTimestamp = ...)` 不生效）。

---

## 2. 哪些接口需要签名（后端视角）

由 `@SystemSecurity` 注解控制，可加在 Controller 类或方法上。

| 注解写法 | 含义 |
|---|---|
| `@SystemSecurity`（默认） | 需要校验参数签名（关键 API 的标准写法） |
| `@SystemSecurity(passSignature = true)` | 放弃参数签名校验（内部 / 公开接口用） |
| `@SystemSecurity(passAll = true)` | 放弃 token / platform / signature / timestamp 全部校验（优先级最高） |

> ⚠️ **注意**：只要接口开启了签名校验，时间戳校验就强制开启，不可单独关闭。

**后端示例**：

```java
@RestController
@RequestMapping("/api/order")
public class OrderController extends AbstractBasicController {

    // 关键 API：默认开启参数签名校验
    @SystemSecurity
    @PostMapping("/create")
    public ResponseData<OrderVO> create(@RequestBody OrderCreateReq req) {
        // ...
    }

    // 公开 / 内部接口：放弃签名校验
    @SystemSecurity(passSignature = true)
    @GetMapping("/public/config")
    public ResponseData<ConfigVO> config() {
        // ...
    }
}
```

**前置条件**：项目需配置 `sa-token.sign.secret-key`（见第 7 节）。未配置时签名校验自动跳过。

---

## 3. 调用方必传 Header（签名三件套）

| Header | 类型 | 必填 | 说明 |
|---|---|---|---|
| `timestamp` | Long(String) | 是 | 13 位毫秒级时间戳（如 `1715077731701`） |
| `nonce` | String | 是 | 仅一次有效的随机字符串；**每次请求必须唯一不重复** |
| `sign` | String | 是 | 按第 4 节算法生成的签名值（小写 32 位 MD5） |

> 以上三个 Header 与全局必传的 `Accept-Language` / `timezone` / `User-Agent` 相互独立，均需按项目框架说明传递。

---

## 4. 签名算法

**核心公式**：

```
sign = MD5( sort(query ∪ body ∪ {timestamp, nonce}) 拼接串 + "&key=" + secretKey )
```

**步骤**：

1. **收集参数**：把所有参与签名的键值对放入一个 Map：
   - 所有 **query 参数**（URL 上 `?` 后的键值对）；
   - 请求 **body**：
     - 若为 JSON 对象：把每个字段展平进 Map（只取最外层 key，嵌套对象保持原格式不展开）；
     - 若为 JSON 数组 / 普通字符串 / 数字：用固定 key `body` 装下整段内容；
   - `timestamp`、`nonce` 两个 Header 的值；
2. **排除** `sign` 自身（若 Map 里不慎含 `sign` 不参与计算）；
3. **忽略** 值为 `null` 的键值对；
4. **按 key 字典序升序排序**；
5. **拼接**：键值对用 `=` 连接，多个键值对之间用 `&` 连接；
6. **追加密钥**：在拼接串尾部加 `&key={secretKey}`（secretKey 即前后端共用的 `sa-token.sign.secret-key`）；
7. **MD5**：对完整字符串做 MD5，取**小写 32 位**十六进制，即得 `sign`。

> `secretKey` 通过 `key=` 拼接，与 Sa-Token 默认签名规则一致；MD5 为小写 32 位。

---

## 5. 计算示例

**示例 A：POST + JSON 对象 body**

```
POST /api/order/create?a=1&b=2
Body: {"c":3, "z":26}
Header: timestamp=1715077731701, nonce=SJLF223SJl892891JLJL
```

参与签名的 Map：`{a=1, b=2, c=3, z=26, nonce=SJLF223SJl892891JLJL, timestamp=1715077731701}`

按 key 字典序排序拼接：

```
a=1&b=2&c=3&nonce=SJLF223SJl892891JLJL&timestamp=1715077731701&z=26
```

追加密钥（假设 `secretKey = techne-secret`）：

```
a=1&b=2&c=3&nonce=SJLF223SJl892891JLJL&timestamp=1715077731701&z=26&key=techne-secret
```

对该串做 MD5（小写 32 位）→ `sign`。

**示例 B：Body 为数组**

```
POST /api/order/batch?a=1&b=2
Body: ["a","b","c"]
```

数组用固定 key `body` 装下整段内容：

```
a=1&b=2&body=["a","b","c"]&nonce=...&timestamp=...&z=26&key=techne-secret
```

（JSON 数组原样作为 value，不做内部展开）

## 6. 调用方生成签名参考实现（Java）

```java
import java.util.*;
import java.security.MessageDigest;

public class SignUtil {
    public static String sign(Map<String, Object> params, String secretKey) {
        // 1. 过滤 null，并用 TreeMap 自动按 key 字典序排序
        Map<String, Object> map = new TreeMap<>();
        for (Map.Entry<String, Object> e : params.entrySet()) {
            if (e.getValue() != null) map.put(e.getKey(), e.getValue());
        }
        // 2. 拼接 k=v&k=v
        StringBuilder sb = new StringBuilder();
        for (Map.Entry<String, Object> e : map.entrySet()) {
            if (sb.length() > 0) sb.append("&");
            sb.append(e.getKey()).append("=").append(e.getValue());
        }
        // 3. 追加密钥
        sb.append("&key=").append(secretKey);
        // 4. MD5 小写 32 位
        return md5(sb.toString());
    }

    private static String md5(String s) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            byte[] b = md.digest(s.getBytes(java.nio.charset.StandardCharsets.UTF_8));
            StringBuilder hex = new StringBuilder();
            for (byte x : b) hex.append(String.format("%02x", x));
            return hex.toString();
        } catch (Exception e) { throw new RuntimeException(e); }
    }
}

// 使用
Map<String, Object> p = new HashMap<>();
p.put("a", 1); p.put("b", 2); p.put("c", 3); p.put("z", 26);
p.put("timestamp", 1715077731701L);
p.put("nonce", "SJLF223SJl892891JLJL");
String sign = SignUtil.sign(p, "techne-secret");
```

> 其它语言（JS / Swift / Kotlin）思路一致：TreeMap 排序 → `k=v` 用 `&` 连接 → 追 `&key=密钥` → MD5 小写。

## 7. 后端配置（application.yml）

```yaml
sa-token:
  sign:
    secret-key: your-secret-key-here   # 必填：调用方与后台共用的签名密钥
    timeout: 300                        # 时间戳允许误差（秒）；超出视为过期重放。取值以 Sa-Token 1.42.0 为准
    save-nonce-expire: 120              # nonce 去重缓存 TTL（秒）；同一 nonce 仅一次有效
```

> 只要 `secret-key` 非空且接口未 `passSignature`，签名校验即生效。密钥需通过安全渠道下发给调用方，**切勿**硬编码在前端代码中。

---

## 8. 防重放机制

- **nonce 一次性**：同一 `nonce` 只能校验通过一次；校验通过后写入缓存（TTL 见 `save-nonce-expire`），重复提交直接拒绝。
- **timestamp 时效**：`timestamp` 与服务器当前时间差必须在允许范围内（见 `timeout`），否则拒绝，防止截获的旧请求被重放。

---

## 9. 失败响应 / 错误码

签名校验失败属于鉴权失败，响应仍在统一响应壳内，`code != 200`：

| 失败原因 | code | message |
|---|---|---|
| 签名无效 / 缺失 `sign` / `nonce` 重复 / `timestamp` 超范围（一切签名异常） | `4001` | 具体原因（i18n：`参数签名认证失败` / `Parameter signature authentication failed`） |

```json
{
  "code": 4001,
  "message": "参数签名认证失败",
  "data": null,
  "time": "2026-07-28T17:12:11.000Z",
  "traceId": "c3d4e5f6-0001-..."
}
```

> 前端统一约定：**只要 `code != 200`，就按失败处理并展示 `message`**。

## 10. 完整请求示例（curl）

```bash
# 假设 secretKey = techne-secret
# 客户端先本地计算 sign（伪代码）：
#   params = {a:1, b:2, c:3, z:26, timestamp:1715077731701, nonce:SJLF223SJl892891JLJL}
#   raw    = "a=1&b=2&c=3&nonce=SJLF223SJl892891JLJL&timestamp=1715077731701&z=26&key=techne-secret"
#   sign   = md5(raw) = "3f9d..."

curl -X POST 'https://api.example.com/api/order/create?a=1&b=2' \
  -H 'Content-Type: application/json' \
  -H 'Accept-Language: zh-CN' \
  -H 'timezone: Asia/Shanghai' \
  -H 'User-Agent: techne/1.0.0 (iPhone 14 pro v16.0; Asia/Shanghai)' \
  -H 'timestamp: 1715077731701' \
  -H 'nonce: SJLF223SJl892891JLJL' \
  -H 'sign: 3f9d...' \
  -d '{"c":3,"z":26}'
```
